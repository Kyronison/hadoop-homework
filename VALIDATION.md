## Что потребовало исправления

- Собственные имена ВМ разрешались также в `127.0.1.1`, поэтому часть сервисов слушала loopback. После исправления `/etc/hosts` и перезапуска они стали доступны по внутренней сети. Метаданные HDFS сохранены.
- `hdfs --daemon status` возвращал 0 даже для остановленного демона. Проверка запуска заменена на положительный текст статуса и живой PID.
- YARN возвращал канонические имена узлов, хотя в настройках использовались IP. Проверка здоровья теперь разрешает эти имена и сравнивает адреса с inventory.

В первоначальном прогоне `python -m unittest discover -s tests -v`: **23 теста, OK, 0 пропусков**. После исправлений: **58 тестов, OK, 0 пропусков**. Синтаксическая проверка Bash, компиляция Python и проверка Bash-блоков ручных инструкций также прошли. При запуске от root пять проверок Bash пропускаются, поэтому такой прогон не эквивалентен указанному результату.

Скрипты установки и проверки HDFS/YARN соответствуют выполненному прогону. Публичный пример inventory содержит условные адреса и имена. Переносимый помощник SSH-пробросов проверен отдельно: состав всех 11 пробросов, локальная привязка портов, проверка аргументов и отсутствие подключения без `--execute`.

Числовая выжимка реальных результатов находится в [checks/results.json](checks/results.json). Из неё исключены адреса ВМ, имена серверов и пути пользователя; это сокращённый отчёт, а не полный исходный журнал.

## Ограничения

Основной доступ с внешнего компьютера реализован через SSH на localhost. Дополнительный Nginx проверен внутри ВМ; прямая HTTPS-публикация не подтверждена. Прямые SSH-пробросы не переписывают абсолютные ссылки Hadoop; для переходов с внутренними адресами описан SOCKS5-вариант.

Автозапуск после перезагрузки ОС не настроен. Сначала запускается HDFS, затем YARN; данные при этом сохраняются, повторное форматирование NameNode не требуется.
